# User Stories — 蛙游记 Froggy Trails (v1)

**组织方式**:用户旅程为主线(Epic = 旅程阶段),Epic 下挂可独立交付的 Story。
**验收标准**:Given / When / Then。
**INVEST**:每个故事力求 Independent / Negotiable / Valuable / Estimable / Small / Testable。
**追溯**:每个故事标注相关画像(P1–P5)与需求编号(FR/NFR)。

图例:画像 P1 碎片放松者 · P2 想旅行没时间者 · P3 Cozy 玩家 · P4 收藏型 · P5 分享型

## Epic 1 — 初见与选择伙伴(Onboarding)
*承接 FR-1。让首次用户在一次会话内选好伙伴并看到完整闭环。*

### US-1.1 选择我的旅行伙伴
- **As** 首次访问的用户(P1/P3),**I want** 从少数小动物(蛙/獭/刺猬)中选一只作为长期伙伴,**so that** 我对它有归属感。
- **验收标准**
  - Given 我首次进入且尚未有存档,When 进入新手引导,Then 展示可选的小动物(数量以素材库为准),每只有原创造型预览。
  - Given 我选定一只并确认,When 确认后,Then 该角色成为我的唯一伙伴且**不可再更换**,并进入命名步骤。
  - Given 我已有存档,When 我再次进入,Then **不再**显示角色选择。
- **映射**:FR-1.1

### US-1.2 给伙伴命名
- **As** 新用户(P1–P5),**I want** 给伙伴起名,**so that** 它是"我的"小家伙。
- **验收标准**
  - Given 我已选定角色,When 我输入名字并确认,Then 名字保存并显示在首页状态栏。
  - Given 我未输入任何名字,When 我尝试继续,Then 提供一个默认名或提示输入(不阻塞流程)。
- **映射**:FR-1.2

### US-1.3 领取新手道具
- **As** 新用户(P1/P3),**I want** 开局获得基础道具,**so that** 我能立刻准备第一次旅行。
- **验收标准**
  - Given 我完成命名,When 进入下一步,Then 库存中出现:一块面包(食物)、一个水壶(装备)、20 三叶草。
- **映射**:FR-1.3

### US-1.4 引导式第一次出发(3–8 分钟)
- **As** 新用户(P1/P3),**I want** 在引导下完成首次"准备行囊→出发",且很快就能看到结果,**so that** 我在首次会话内体验到完整闭环。
- **验收标准**
  - Given 我持有新手道具,When 引导提示我把道具放入行囊并出发,Then 首趟旅行时长被压缩到 **3–8 分钟**。
  - Given 首趟结束,When 我回到应用,Then 我能看到至少一张明信片/一次归来反馈,完成"准备→等待→反馈"闭环。
- **映射**:FR-1.4, FR-5.4

## Epic 2 — 小屋日常(Home & Courtyard)
*承接 FR-2。首页是产品最重要的页面。*

### US-2.1 查看小屋首页与伙伴状态
- **As** 回访用户(P1/P2/P3),**I want** 打开就看到庭院场景与伙伴当前状态,**so that** 我快速知道"现在发生了什么"。
- **验收标准**
  - Given 我进入首页,When 页面加载完成,Then 桌面端显示左侧场景(~65%)+ 右侧状态栏(~35%);移动端为响应式堆叠。
  - Given 状态栏渲染,When 我查看,Then 显示:伙伴名、心情、当前状态、当前资源、"准备行囊"入口、最近一张明信片、未读邮件、季节/天气氛围。
- **映射**:FR-2.1, FR-2.2

### US-2.2 采集庭院资源(无压力)
- **As** 碎片放松者(P1),**I want** 一次操作就收取庭院产出且离线不受损,**so that** 我没有签到/收菜压力。
- **验收标准**
  - Given 庭院已周期性生成三叶草/四叶草/露珠,When 我进行一次采集操作,Then 资源一次性进入库存。
  - Given 我很久没上线,When 我回来,Then 资源**不过期、不减少**,离线不产生任何损失。
  - Given 资源已满上限(若有),When 继续生成,Then 以设计上限处理而非惩罚用户。
- **映射**:FR-2.3, NFR-3

### US-2.3 首页氛围动效
- **As** Cozy 玩家(P3),**I want** 首页有轻微的环境动效,**so that** 有治愈的"活着"的感觉。
- **验收标准**
  - Given 首页展示,When 空闲时,Then 出现树叶摇动、云移动、伙伴偶尔眨眼等氛围动效。
  - Given 有新邮件到达,When 首页可见,Then 邮箱轻晃提示。
  - Given 动效运行,When 用户交互,Then 动效不阻塞点击/滚动等操作。
- **映射**:FR-2.4, NFR-2

## Epic 3 — 准备与出发(Backpack & Departure)
*承接 FR-4、FR-3。*

### US-3.1 组装行囊(四槽位)
- **As** 玩家(P1/P3/P4),**I want** 把食物/护符/装备放入四个槽位,**so that** 我能"影响"但不直接决定旅行。
- **验收标准**
  - Given 我打开行囊,When 我从库存拖入/放入槽位(食物、护符、装备A、装备B),Then 槽位显示所选物品。
  - Given 某槽位已占用,When 我放入新物品,Then 允许替换并把原物品退回库存。
- **映射**:FR-4.1, FR-4.2

### US-3.2 只看到模糊倾向,不看到目的地
- **As** 想旅行没时间者(P2),**I want** 只得到氛围化的倾向提示,**so that** 保留旅行的未知与惊喜。
- **验收标准**
  - Given 我在行囊中放入物品,When 系统给出提示,Then 只显示模糊倾向(如"似乎适合寒冷地区""也许会走得更远"),**绝不显示**具体目标地点。
- **映射**:FR-4.3

### US-3.3 确认行囊并出发
- **As** 玩家(P1/P3),**I want** 确认行囊后让伙伴出发,**so that** 开始一段旅行。
- **验收标准**
  - Given 我确认行囊,When 确认成功,Then 状态从 `HOME_IDLE` 进入 `PACK_READY`,出现"出发"入口。
  - Given 我点击出发,When 出发成功,Then 状态进入 `DEPARTING→TRAVELING`,并记录出发/预计到达/归来时间与 `random_seed`。
- **映射**:FR-4.4, FR-3.1, FR-5.1

## Epic 4 — 等待与旅行(Waiting & Travel)
*承接 FR-3、FR-5。产品的技术核心:客户端惰性、可复现结算。*

### US-4.1 旅行途中的氛围状态
- **As** 想旅行没时间者(P2),**I want** 途中只看到氛围文字而非实时定位,**so that** 保留想象空间。
- **验收标准**
  - Given 伙伴处于 `TRAVELING`,When 我查看首页,Then 只显示氛围型状态文字(如"正在向很远的地方走去""今天似乎遇到了雨"),**不展示实时 GPS/精确坐标**。
- **映射**:FR-3.2

### US-4.2 惰性推进与可复现结算
- **As** 玩家(P1/P3),**I want** 我不在时旅行也照常"进行",回来即看到结果,**so that** 我不必一直盯着。
- **验收标准**
  - Given 出发时已记录时间线与 `random_seed`,When 我在任意时间打开应用,Then 系统依据当前时间确定性地推进状态并结算旅行产物。
  - Given 相同 `random_seed`、相同行囊与相同时间线,When 重新结算,Then 结果**完全可复现**(相同目的地/明信片/事件)。
  - Given 到达/归来时间已过,When 我打开,Then 状态正确推进到 `RETURNING/HOME_IDLE` 并触发对应产物。
- **映射**:FR-5.5, FR-5.1, NFR-7

### US-4.3 目的地由行囊与随机共同决定
- **As** Cozy 玩家(P3),**I want** 行囊选择影响目的地概率但不完全控制,**so that** 每次都有惊喜又有参与感。
- **验收标准**
  - Given 我的行囊与季节等因素,When 结算目的地,Then 依据加权评分(BaseWeight×EquipmentMatch×FoodMatch×SeasonMatch×NoveltyBoost×RarityFactor×RandomFactor)选出结果。
  - Given 我连续访问同一区域,When 下次结算,Then 未访问区域获得轻度概率提升(NoveltyBoost),但重复旅行仍可能发生且仍产出内容。
  - Given 任一旅行完成,When 查看产物,Then 至少产出"故事/地点/收藏"三类中的两类。
- **映射**:FR-5.2, FR-5.3, FR-5.6

## Epic 5 — 归来与收获(Return: Postcards, Souvenirs, Notice)
*承接 FR-6、FR-9、FR-12。*

### US-5.1 收到明信片(卡片滑入)
- **As** 想旅行没时间者(P2),**I want** 以有仪式感的方式收到明信片,**so that** 每次归来都值得期待。
- **验收标准**
  - Given 旅行产出明信片(途中 0–2 张 + 归来 0–1 张),When 我打开应用,Then 明信片以**卡片滑入桌面**的方式呈现,而非普通 Toast。
  - Given 明信片展示,When 我查看,Then 含地点、场景、姿势、天气、日记文案、稀有度表现与图片(来自预制素材库)。
- **映射**:FR-6.1, FR-6.2, FR-6.3, FR-6.5

### US-5.2 稀有度的克制表现
- **As** 收藏型(P4),**I want** 稀有明信片有独特但不"抽卡"的表现,**so that** 收藏有惊喜且不廉价。
- **验收标准**
  - Given 一张稀有明信片,When 展示,Then 通过纸张/烫金边框/特殊邮戳/星空纸/手绘签名/限定季节纸等表现稀有度。
  - Given 任意稀有表现,When 呈现,Then **不使用** SSR/抽卡等赌博式话术。
- **映射**:FR-6.4, NFR-8

### US-5.3 获得纪念品
- **As** 收藏型(P4),**I want** 旅行带回纪念品,**so that** 我有可收集的实感物件。
- **验收标准**
  - Given 伙伴归来,When 结算纪念品,Then 按该地点的纪念品池(每地 3–8 个,可含"无意义但有情绪"的物件)发放并计入收藏。
- **映射**:FR-9.1, FR-9.2

### US-5.4 归来与到信的应用内提示
- **As** 碎片放松者(P1),**I want** 打开时清楚知道"有新东西",**so that** 我不错过反馈。
- **验收标准**
  - Given 伙伴已归来或有新明信片,When 我打开应用,Then 以带故事感的文案给出应用内提示(v1 不含系统推送)。
- **映射**:FR-12.1

## Epic 6 — 收集与回顾(Album & Map)
*承接 FR-7、FR-8。*

### US-6.1 手帐式旅行相册
- **As** 收藏型(P4),**I want** 以手帐/剪贴簿方式回顾旅行,**so that** 回顾本身就是享受。
- **验收标准**
  - Given 我打开相册,When 浏览,Then 采用跨页布局:左页大图明信片,右页日期/地点/天气/邮戳/日记/纪念品/地点知识。
  - Given 我尚无任何旅行,When 打开相册,Then 显示引导性空状态而非空白。
- **映射**:FR-7.1

### US-6.2 世界地图迷雾点亮
- **As** 收藏型(P4)/想旅行没时间者(P2),**I want** 看到"它去过哪里"并逐渐点亮地图,**so that** 我有探索世界的成就感。
- **验收标准**
  - Given 地图初始状态,When 我打开,Then 覆盖轻度迷雾,地点状态可为:未发现/听说过/去过/多次到访/完成收藏。
  - Given 伙伴访问了某地点,When 结算后,Then 对应地点在地图上点亮并更新状态。
  - Given v1 使用内置种子地点数据,When 渲染地图,Then 使用静态点亮效果(不接实时 tile/外部 API)。
- **映射**:FR-8.1, FR-8.2, FR-8.3, FR-8.4

## Epic 7 — 分享(Share)
*承接 FR-7.2。*

### US-7.1 生成漂亮的分享卡
- **As** 分享型(P5),**I want** 一键生成好看的分享卡,**so that** 我愿意把它发出去。
- **验收标准**
  - Given 我在某张明信片/某次旅行,When 我点击"生成分享卡",Then 输出含 画面 + 地名 + 日期 + 一句话 + 品牌角标 的图片。
  - Given 分享卡生成,When 我操作,Then 可下载/保存到本地(v1 不做站内社交发布)。
- **映射**:FR-7.2

## Epic 8 — 经济与商店(Clover Economy & Shop)
*承接 FR-2.3、FR-10。*

### US-8.1 用三叶草在商店购买
- **As** Cozy 玩家(P3),**I want** 用庭院产出的软货币购买道具/装饰,**so that** 我有可持续的养成动力且无付费压力。
- **验收标准**
  - Given 我有三叶草,When 我在商店购买食物/装备/装饰,Then 扣除对应三叶草并把物品加入库存。
  - Given 我三叶草不足,When 我尝试购买,Then 提示不足且不扣款。
  - Given 我在商店任意操作,When 结账,Then **不出现任何真实支付入口**(v1 无内购)。
- **映射**:FR-10.1, FR-10.2

## Epic 9 — 存档、语言与设置(Local Save, i18n, Settings)
*承接 FR-11、FR-13。*

### US-9.1 本地自动存档
- **As** 所有用户(P1–P5),**I want** 我的进度自动保存在本地,**so that** 我下次打开能无缝继续。
- **验收标准**
  - Given 我进行了任意进度变化(采集/出发/归来/购买),When 变化发生,Then 数据自动写入浏览器 IndexedDB。
  - Given 我重新打开应用,When 加载,Then 恢复到上次的完整状态(含进行中的旅行时间线与 seed)。
- **映射**:FR-11.1, FR-11.2, FR-11.3

### US-9.2 中英双语切换
- **As** 用户(P1–P5),**I want** 在中英文之间切换界面语言,**so that** 我用熟悉的语言游玩。
- **验收标准**
  - Given 我在设置中切换语言,When 切换,Then 界面文案立即在中/英之间更新。
  - Given 某些内容文案英文暂缺,When 显示,Then 优雅回退到中文(不出现空白/占位键名)。
- **映射**:FR-13.1

## Epic 10 — 质量与技术类故事(NFR-bearing)
*承接关键 NFR;Q5=A 要求单独承载。*

### US-10.1 离线可玩
- **As** 碎片放松者(P1),**I want** 在无网络时仍能进行核心玩法,**so that** 通勤等弱网场景不受影响。
- **验收标准**
  - Given 静态资源已加载,When 我处于离线,Then 采集/准备/出发/惰性结算/查看相册地图等核心操作仍可用。
- **映射**:NFR-3

### US-10.2 清除数据的丢档提示(诚实边界)
- **As** 用户(P1–P5),**I want** 清楚知道 v1 存档是本地的,**so that** 我不会意外丢失且有预期。
- **验收标准**
  - Given v1 无云同步,When 用户首次产生重要进度(如收到稀有明信片)或在设置中查看,Then 明确告知"进度保存在本设备,清除浏览器数据会丢失",并预告未来可登录云同步。
- **映射**:FR-11.4, FR-5(seed), NFR-7

### US-10.3 尊重"减少动效"偏好与基本无障碍
- **As** 对动效敏感/使用辅助技术的用户,**I want** 应用尊重系统偏好并可键盘操作,**so that** 我能舒适、可达地使用。
- **验收标准**
  - Given 系统开启 `prefers-reduced-motion`,When 我使用应用,Then 氛围/滑入等动效相应减弱或关闭。
  - Given 我用键盘导航,When 操作主要交互(采集/行囊/出发/商店),Then 元素可聚焦、可操作,并有足够对比度与图片替代文本。
- **映射**:NFR-5

### US-10.4 视觉风格一致性(原创且 cozy)
- **As** Cozy 玩家(P3)/产品,**I want** 全站遵循统一的手帐 watercolor 视觉且完全原创,**so that** 品牌统一且规避 IP 风险。
- **验收标准**
  - Given 任意界面,When 渲染,Then 遵循 PRD §25 视觉(暖纸张/苔藓绿系配色、圆角卡片、弱阴影、手绘图标),避免 SaaS 风与大量数值/进度条。
  - Given 所有插画/角色/明信片素材,When 使用,Then 均为原创或合规授权,不复刻《旅行青蛙》任何具体资产。
- **映射**:NFR-6, NFR-8
